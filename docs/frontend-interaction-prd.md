# Omo MVP 前端交互 PRD

- 状态：产品验收基线，待产品逐项复核
- 范围：iOS MVP 前端交互
- 目的：统一产品、设计、开发与测试对“用户在每个状态下看到什么、能做什么、失败后如何继续”的理解
- 说明：本文描述目标交互，不代表当前 TestFlight 构建已经全部满足

## 1. 产品主线

Omo 只围绕一条主线工作：

```text
用户保存一张自己认为有价值的截图
→ Omo 自动处理并生成一张知识卡
→ 用户通过 IP 抽取最多十张待复习卡
→ 先尝试回忆，再刮开承重语义
→ 用户滑动自评
→ Omo 安排下一次复习
```

首页只有三个核心入口：

- IP：开始抽卡与主动回忆。
- 收藏夹：进入知识库，浏览所有完整知识卡和处理状态。
- 加号：从系统相册选择一张新截图。

侧边菜单只承载 Profile 和 Settings，不与三个核心入口竞争注意力。

## 2. 全局硬规则

以下规则适用于所有页面和状态，也是测试的第一优先级：

1. 除系统照片选择器、系统权限弹窗和必要确认弹窗外，不允许出现整页交互锁死。
2. 处理一张截图时，菜单、收藏夹和加号仍可使用；若已有可复习卡，IP 也仍可使用。
3. 任何超过合理等待时间的操作必须结束为成功或明确失败，不得无限显示“正在处理”。
4. App 被切到后台、系统中断或被用户杀掉后，再次打开必须恢复真实状态，不能仅清掉界面提示。
5. 每个失败状态至少提供一个低成本恢复动作：重试、重新上传、清除搜索或返回。
6. 页面上看起来像按钮的元素必须能点击；不能点击的元素不得使用按钮动效、箭头引导或 VoiceOver 按钮语义。
7. 用户已经生成的知识卡不能因页面切换、请求失败或重新启动而消失。
8. Fixture、Mock 和静态截图只用于开发；TestFlight 验收必须连接独立 Omo staging，并使用最终待测构建。
9. 揭示前不得在可见文字、无障碍信息、详情入口或状态恢复中泄露被遮住的答案。
10. 稀有度只负责视觉氛围，不增加确认步骤，也不影响复习调度。

## 3. 用户故事

1. 作为第一次使用 Omo 的用户，我希望首页直接引导我上传自己的截图，从而尽快体验第一张属于我的知识卡。
2. 作为用户，我希望取消系统照片选择后原样回到首页，不产生空任务或错误提示。
3. 作为用户，我希望截图开始处理后仍可进入知识库或继续上传，而不是被锁在等待状态。
4. 作为用户，我希望处理时间较长时能确认任务仍然存在，而不是猜测 App 是否卡死。
5. 作为用户，我希望处理失败时得到明确反馈和重试入口。
6. 作为用户，我希望关闭并重新打开 App 后仍能看到正在处理、成功或失败的真实结果。
7. 作为用户，我希望第一张卡生成成功后，首页明确把注意力转向可点击的 IP。
8. 作为用户，我希望收藏夹在空库、处理中和有卡时都能打开。
9. 作为用户，我希望知识库直接展示完整知识，不需要再次刮开。
10. 作为用户，我希望能从知识库继续上传截图。
11. 作为用户，我希望通过文字或语音描述找回模糊记得的知识卡。
12. 作为用户，我希望点击 IP 后一次抽取最多十张可复习卡；不足十张就复习现有全部卡片。
13. 作为用户，我希望抽卡动画结束后直接看到第一张未揭示的卡，而不是再做一次确认。
14. 作为用户，我希望在当前卡片下隐约看到下一张卡的稀有度光效，增加期待感。
15. 作为用户，我希望只刮开真正需要回忆的关键词或承重语义，不必刮整张卡。
16. 作为用户，我希望局部刮开时只看到被刮到的区域。
17. 作为用户，我希望刮开达到 80% 后自动完全揭示，并出现自评滑条。
18. 作为用户，我希望揭示后的答案通过字重和颜色与上下文形成明确层级。
19. 作为用户，我希望拖动自评时通过节点震动、轨道颜色和位置理解当前选择。
20. 作为用户，我希望拖回最左侧松手可以取消本次自评，卡片不切换。
21. 作为用户，我希望在三个自评节点松手后立即确认并自动进入下一张卡。
22. 作为用户，我希望自评提交失败时留在当前已揭示卡，并能重试，避免误以为结果已保存。
23. 作为用户，我希望在回顾过程中仍可打开收藏夹或上传截图。
24. 作为用户，我希望通过卡片的次级入口查看更完整上下文，但它不是完成回顾的必经步骤。
25. 作为用户，我希望问题通知在 App 外戳中“我到底还记不记得”，点击后直接进入对应的未揭示卡。
26. 作为用户，我希望通知卡完成后回到原来的首页状态，而不是进入另一套做题页面。
27. 作为使用 VoiceOver、较大字号或减少动态效果的用户，我希望所有核心动作仍完整可用。

## 4. 首页固定结构

首页是抽卡和复习发生的主场景，不跳转到独立“做题页”。固定结构包括：

- 左上：侧边菜单按钮。
- 中央主要区域：IP；有可复习卡时是抽卡入口。
- 下方主体：收藏夹视觉；点击进入知识库。
- 右下：加号；点击打开 iOS 系统照片选择器。
- 卡片层：抽卡后叠加在首页主体上，不移除收藏夹和加号。

具体 IP 形象和动画不由本文定义；但 IP 的可点击与不可点击状态必须能被用户分辨。

### 4.1 首页入口可用性矩阵

| 首页状态 | 菜单 | IP | 收藏夹 | 加号 | 当前卡交互 |
|---|---:|---:|---:|---:|---:|
| 首次空库 | 可用 | 不抽卡 | 可用 | 可用 | 无 |
| 只有截图处理中 | 可用 | 无可复习卡时不抽卡 | 可用 | 可用 | 无 |
| 处理中且已有可复习卡 | 可用 | 可用 | 可用 | 可用 | 无 |
| 有可复习卡、首页空闲 | 可用 | 可用 | 可用 | 可用 | 无 |
| 抽卡动画 | 可用 | 本次抽取中不重复触发 | 可用 | 可用 | 动画结束后可用 |
| 刮开中 | 可用 | 不重复触发 | 可用 | 可用 | 可用 |
| 等待自评 | 可用 | 不重复触发 | 可用 | 可用 | 可用 |
| 自评提交中 | 可用 | 不重复触发 | 可用 | 可用 | 防止重复提交 |
| 自评失败 | 可用 | 不重复触发 | 可用 | 可用 | 重试可用 |
| 通知卡叠加 | 可用 | 不重复触发 | 可用 | 可用 | 通知卡可用 |
| 首页数据加载失败 | 可用 | 仅在已有本地可用卡时可用 | 可用 | 可用 | 重试加载可用 |

空库时点击收藏夹进入“空知识库”，而不是没有响应。空库 IP 不启动抽卡，也不显示指向 IP 的抽卡箭头。

## 5. 首次使用与截图上传

### 5.1 首次空库

用户第一次进入且没有知识卡或处理任务时：

- 首页只突出“上传第一张知识截屏”。
- 箭头指向加号。
- 不预置示例卡或他人的截图。
- 收藏夹可以点击，进入空知识库。
- IP 不承担抽卡动作，也不伪装成可点击入口。

### 5.2 打开照片选择器

1. 用户点击加号。
2. App 打开 iOS 系统照片选择器，只选择一张图片。
3. 用户取消：关闭选择器，首页状态不变，不创建任务。
4. 用户确认图片：App读取并压缩图片。
5. 图片读取失败：回到原页面，显示简短错误；加号保持可用。

### 5.3 首次 AI 处理许可

首次把截图发送给 AI 前显示系统风格确认弹窗：

- 取消：不上传、不创建处理任务，回到原页面。
- 同意并生成：记住许可，开始当前截图处理。
- 撤回许可后，下次上传重新询问。

许可弹窗是上传前唯一允许暂时阻断页面操作的产品弹窗。

### 5.4 截图处理开始

用户同意后：

1. 立即回到首页。
2. 创建一条可恢复的截图处理记录，而不是只保存一个内存中的转圈状态。
3. 首页以轻量方式显示“正在整理第一张知识卡”或对应处理数量。
4. 收藏夹内能看到该截图对应的处理中占位项。
5. 菜单、收藏夹和加号保持可用；已有可复习卡时 IP 保持可用。
6. 自动执行来源识别和溯源，不额外询问用户是否溯源。

实现状态（2026-08-08）：App 内首页与知识库入口已共用同一个上传状态协调器；每张截图使用独立持久任务，其他截图处理中不会禁用菜单、收藏夹、加号或已有卡片的抽取入口。

同一张截图的重复提交不得产生互相冲突的重复卡；界面应回到同一条 canonical 处理结果。

### 5.5 处理成功

处理成功后：

- 处理中占位项替换为完整知识卡。
- 卡片立即出现在知识库。
- 该卡满足召回合同且到期时，进入可抽取卡池；MVP 不强制等待 24 小时。
- 如果这是第一张可抽取卡，首页引导从加号切换到 IP。
- IP 变成可点击抽卡入口。
- 不强制自动开始抽卡，决定权仍在用户。

来源自动匹配失败不等于整张卡失败：只依据截图生成卡，来源状态如实标记，稀有度保持最低等级 R。

### 5.6 处理失败与超时

模型、网络、服务配置或数据格式失败时：

- 结束“处理中”，不得无限等待。
- 首页给出简短失败反馈，但不覆盖所有入口。
- 知识库中的处理项显示失败状态和“重试”。
- 重试复用同一个处理记录，不额外制造重复卡。
- 用户也可以通过加号重新选择图片。
- 不用 Fixture、静态卡或假成功替代真实失败。

MVP 不要求用户纠正 AI 内容，也不要求失败后手动补来源链接。

### 5.7 进入后台与重新启动

- App 进入后台时，前端不得把任务标记为完成或失败。
- 用户杀掉 App 再打开，首页先加载卡片和未完成任务。
- 后端仍在处理：恢复“处理中”占位，其他入口可用。
- 后端已成功：显示新卡并启用 IP。
- 后端已失败或任务已超时：显示失败和重试。
- 找不到任务记录：明确显示任务中断，不允许静默消失。

“杀掉 App 后处理中提示消失、卡片也不存在”属于验收失败。

实现状态（2026-08-08）：iOS 启动会合并本地与服务端任务并恢复轮询；服务端已经成功时同时刷新卡片并清除本地重试图片，失败任务继续提供同 ID 重试。最终 TestFlight 真机结果仍以本 PRD 验收清单为准。

### 5.8 Share Extension 外部入口

截图后的系统分享是 Omo 预期的主要日常保存入口；App 内加号同时承担首次体验和补充入口。

- 用户在系统截图或照片分享面板选择 Omo。
- Share Extension 不要求填写标题、分类、关键词或其他表单。
- 已完成 AI 处理授权时，扩展先把截图可靠交给 Omo，再显示简短成功反馈并允许关闭；成功只表示任务已被接收，不冒充知识卡已生成。
- 首次尚未完成 AI 处理授权时，扩展不得静默上传；应引导打开 Omo 完成一次授权，再继续处理该截图。
- 任务接收后，App 首页和知识库显示与 App 内上传相同的处理中、成功或失败状态。
- 扩展提交失败时保留明确重试或打开 Omo 的动作，不能显示假成功。
- 重复分享同一张截图遵循同一个 canonical 处理结果。

MVP 不把“敲击手机背面”等系统手势作为必须交付能力；它可以在后续作为触发 Share Extension 或 Shortcut 的快捷方式研究。

## 6. 有卡首页与抽卡

### 6.1 IP 可点击条件

只有存在至少一张满足以下条件的卡时，IP 才启动抽卡：

- 已完成生成并持久化；
- 有合法的承重语义；
- 当前已到复习时间；
- 未处于删除或失败状态。

存在知识卡但暂时没有待复习卡时，收藏夹和加号仍可用；IP 不伪装成可抽取状态。

### 6.2 默认十连抽

- MVP 只有默认十连抽。
- 每轮从当前可复习卡池取最多 10 张。
- 少于 10 张时抽取剩余全部卡片。
- 点击 IP 的瞬间冻结本轮卡片和顺序；本轮中新生成或重新调度的卡不插入中途。
- MVP 不提供单抽、分类抽取、关键词选择或文字保底说明。

### 6.3 抽卡呈现

1. 用户点击 IP。
2. 播放抽取反馈与卡堆出现动画。
3. 动画结束直接显示第一张未揭示卡。
4. 卡堆最多呈现四层视觉深度，不等于四张或四种稀有度。
5. 下一张卡可以从被压住的边缘隐约发光，提前暗示其稀有度。
6. 当前卡稀有度可以随卡出现而显示；它不是需要点击查看的步骤。

Reduce Motion 开启时缩短或移除装饰位移，但必须直接进入相同的第一张卡状态。

## 7. 回忆卡与刮刮乐

### 7.1 卡片内容

卡片显示一条连续知识表达：

- 普通上下文直接显示。
- 只有承重语义被刮层遮住。
- 用户先根据问题和可见上下文尝试回忆。
- 原截图不直接作为卡面答案；截图只是 AI 恢复来源和生成知识的锚点。

### 7.2 局部刮开

- 手指只擦除经过区域的遮罩。
- 刮开一点，只显示对应区域的关键词文字。
- 覆盖率低于 80% 时不显示自评滑条。
- 刮开进度不因短暂触碰、页面重绘或旋转而意外归零。
- 刮层只接收卡片语义区域内的手势，不抢占收藏夹、加号或系统返回手势。

### 7.3 达到揭示阈值

达到 80% 后：

1. 自动归一为 100% 完全揭示。
2. 触发一次轻震动。
3. 显示完整承重语义。
4. 出现自评滑条。
5. 已揭示文字使用更强字重和强调色；普通上下文保持较弱权重。

不提供额外“直接揭晓”按钮，也不要求再次点击确认揭示。

### 7.4 完整上下文

- 完整上下文是卡片上的次级入口，不是必经步骤。
- 主动回忆卡在揭示前不能通过详情绕过答案遮挡。
- 揭示后可展开详情，查看完整知识、简短解释、来源标题、账号、平台、链接和真实来源状态。
- 关闭详情回到同一张卡，保留刮开和自评状态。
- 知识库内打开详情时直接显示完整内容，不使用刮层。

## 8. 滑动自评

### 8.1 结构

滑条从左到右包含四个释放位置：

1. 最左取消区；
2. 忘了；
3. 没记清；
4. 记住了。

滑条只在答案完全揭示后出现。

### 8.2 拖动反馈

- 用户从最左侧拖动箭头。
- 经过每个正式节点时触发一次轻震动。
- 轨道是预先定义好的完整渐变；拖动位置只决定填充到渐变的哪个位置。
- 已填充部分显示该位置对应的渐变颜色，不重新计算为“起点色到当前色”的双色渐变。
- 箭头保持固定颜色，不跟随轨道渐变。
- 节点、描边或投影可随当前选择变化，但不能比卡片答案更抢注意力。

### 8.3 松手结果

- 在最左取消区松手：取消自评，箭头回到起点，卡片保持完全揭示，不切换。
- 在“忘了”节点松手：提交 forgot。
- 在“没记清”节点松手：提交 fuzzy。
- 在“记住了”节点松手：提交 remembered。
- 在两个节点之间松手：吸附到最近的有效节点后提交；取消区仍只执行取消。
- 一次松手只提交一次，不增加二次确认按钮。

### 8.4 提交成功与失败

成功：

- 保存自评结果和下一次复习时间。
- 当前卡退出，下一张卡进入并恢复完全遮挡。
- 最后一张成功后结束本轮，回到首页空闲状态。

失败：

- 留在当前已揭示卡。
- 保留刚才选择的位置和明确错误反馈。
- 提供重试，不自动跳到下一张。
- 防止连续松手产生重复 assessment。

## 9. 回顾过程中的离开与返回

- 首页不增加专门的中途关闭按钮。
- 打开系统照片选择器、AI 许可弹窗或卡片详情属于临时叠层；关闭后回到同一张卡并保留当前状态。
- 进入知识库、Profile 或 Settings 属于离开当前轮次；已经成功提交的自评保留，未提交卡片的局部刮开不保存。
- 返回首页后不恢复半轮，用户再次点击 IP 开始一轮新的最多十张牌组。
- App 被系统终止时同样不恢复半轮，但不得丢失已成功提交的自评。

## 10. 知识库

知识库是次级页面，用于直接浏览和主动找回，不是复习页面。

### 10.1 进入与退出

- 首页点击收藏夹进入知识库。
- 空库也能进入，并显示上传入口。
- 返回按钮回到首页。
- 知识库加号打开相同的系统照片选择流程。

### 10.2 卡片与处理项

- 已完成卡片直接显示完整知识，不刮开、不提问。
- 点击卡片打开完整上下文。
- 正在处理的截图显示占位项和真实状态，不混入搜索结果。
- 失败的处理项显示重试入口。
- 页面放不下时根据实际卡片高度分页，不按文字字数硬编码。

### 10.3 文字搜索

- 输入文字并点击搜索或键盘 Search 提交。
- 空白输入不发请求。
- 新搜索取消旧搜索；旧结果不能覆盖新查询。
- 清空输入立即恢复全部卡片并回到第一页。
- 加载、结果、无结果和失败必须是四个不同状态。
- 搜索失败保留查询，并提供重试或清除。

### 10.4 语音搜索

- 点击麦克风后按系统流程请求权限。
- 授权后显示监听状态和实时转写。
- 停止语音后把最终文字作为同一搜索框的查询提交。
- 拒绝权限时说明原因并提供进入 Settings 的恢复入口。
- 离开页面、开始文字搜索或系统中断时停止录音。

知识库更完整的分页、搜索和语音规则见 [[docs/knowledge-library-prd]]。

## 11. 问题通知

通知用于模拟未来“想用却想不起来”的痛点，不直接把答案塞给用户。

示例：

```text
通知：为什么保存截图，有时反而会让你更难记住内容？

点击后卡片：
截图可能削弱记忆，因为它会触发 █████：用户认为设备已经替自己保存。
```

交互规则：

- 通知问题来自某一张具体卡的 recall cue。
- 通知标题、正文和 payload 不包含承重语义或答案。
- 点击通知后打开首页，并在当前首页之上叠加对应未揭示卡。
- 不跳转到独立通知页，也不重新抽取十张卡。
- 通知卡使用与普通卡相同的刮开和自评逻辑。
- 完成后关闭通知卡，回到通知前的首页状态。
- 卡片已删除、不可召回或加载失败时，显示可理解反馈并回到首页，不能展示错误卡或空白层。

## 12. 侧边菜单、Profile 与 Settings

- 点击左上菜单打开侧边抽屉；点击遮罩关闭。
- 抽屉只包含 Profile 和 Settings。
- Profile、Settings 都能明确返回首页。
- AI 处理许可可以在 Settings 撤回。
- 隐私说明和联系支持保持可访问。
- 打开菜单时底层页面不可误触；关闭菜单后恢复原状态。

## 13. 反馈、动效与可访问性

### 13.1 触觉反馈

- 点击 IP 开始抽取：一次选择反馈。
- 刮开达到 80%：一次轻震动。
- 自评经过有效节点：每个节点一次轻震动。
- 自评提交成功：轻量完成反馈。
- 失败不使用成功震动。

### 13.2 触控

- 菜单、IP、收藏夹、加号、返回、详情、搜索、麦克风、重试和滑条有效区域至少 44 × 44 pt。
- 装饰图片不拦截其上方或附近按钮的点击。
- 卡片手势不能覆盖系统边缘返回或底层持久入口。

### 13.3 Dynamic Type、VoiceOver 与 Reduce Motion

- 大字号允许页面纵向滚动，不截断核心知识和主要动作。
- VoiceOver 在揭示前只能读到问题、可见上下文和“答案仍被遮挡”，不能读出承重语义。
- 揭示后再把完整句子加入无障碍阅读。
- IP 只有可抽卡时才具有按钮语义。
- Reduce Motion 关闭装饰位移，但不删除抽卡完成、揭示完成、自评节点和换卡的因果反馈。

## 14. 错误与恢复矩阵

| 场景 | 用户看到 | 用户仍可做 | 不允许发生 |
|---|---|---|---|
| 首页卡片加载失败 | 简短错误与重试 | 菜单、收藏夹、上传、重试 | 整页空白或永久转圈 |
| 图片读取失败 | 读取失败提示 | 重新选择、返回 | 创建幽灵任务 |
| 截图处理中 | 真实处理中状态 | 浏览知识库、继续上传、复习旧卡 | 禁用全部入口 |
| 生成超时 | 失败状态与重试 | 重试、重新上传、浏览旧卡 | 无限显示处理中 |
| App 重启时任务未完成 | 恢复处理中项 | 使用其他入口 | 任务静默消失 |
| 来源匹配失败 | 截图生成的 R 卡与真实来源状态 | 正常浏览和复习 | 伪造原文或阻止生成 |
| 自评提交失败 | 当前已揭示卡和重试 | 重试、浏览/上传 | 自动换卡 |
| 搜索无结果 | 明确无结果 | 改查、清除、查看全部 | 显示为系统错误 |
| 搜索失败 | 错误与重试 | 重试、清除、返回 | 保留伪旧结果 |
| 通知目标卡不存在 | 轻提示后回首页 | 使用首页全部有效入口 | 空白遮罩或崩溃 |

## 15. 前端验收清单

任何构建只有完成以下实际操作，才能声明“前端交互通过”。

### 15.1 验收环境

- 使用准备提交给测试员的同一个 Archive/IPA，而不是另一个 Debug Bundle。
- 至少覆盖一个真实 iPhone；Simulator 作为补充，不替代真机。
- Release 连接独立 Omo staging；验收记录写明 App ID、Bundle ID、版本和 build number。
- 正常路径使用真实服务；Mock 状态必须单独标记。

### 15.2 首页与上传

- [ ] 空库首页：菜单、收藏夹、加号逐个实际点击。
- [ ] IP 空库状态不会误触发抽卡，也不会表现成坏掉的按钮。
- [ ] 照片选择取消后首页无副作用。
- [ ] 首次 AI 许可取消和同意分别验证。
- [ ] 上传开始后逐个点击菜单、收藏夹和加号。
- [ ] 处理旧卡期间点击 IP，确认不受新任务阻塞。
- [ ] 真实截图生成成功并在首页、知识库和重新启动后存在。
- [ ] 人为制造慢请求，确认界面不锁死。
- [ ] 人为制造超时/断网，确认结束为失败并可重试。
- [ ] 处理中切后台再返回，状态正确。
- [ ] 处理中杀掉 App 再打开，任务恢复为处理中、成功或失败之一，不能消失。
- [ ] 从系统分享面板提交截图，确认任务进入与 App 内上传相同的状态链。
- [ ] Share Extension 首次未授权、接收成功、接收失败和重复分享分别验证。

### 15.3 抽卡、刮开与自评

- [ ] 1 张、少于 10 张和至少 10 张三种牌组分别验证。
- [ ] 点击 IP 只触发一次抽取。
- [ ] 四层牌堆和下一张稀有度光效不承担额外交互。
- [ ] 79% 不显示自评；80% 自动完整揭示。
- [ ] 揭示前通过视觉和 VoiceOver 都读不到答案。
- [ ] 揭示后文字字重和颜色层级正确。
- [ ] 滑条完整渐变、固定色箭头和三个节点反馈正确。
- [ ] 最左取消不切卡；forgot、fuzzy、remembered 各提交一次。
- [ ] 自评失败留在当前卡并可重试。
- [ ] 下一张重新完全遮挡；最后一张后返回首页。
- [ ] 回顾中收藏夹和加号逐个实际点击。

### 15.4 知识库与通知

- [ ] 空库、处理中、失败、单卡、多页完整卡分别验证。
- [ ] 知识库卡片无需刮开，详情完整。
- [ ] 文字搜索：加载、结果、无结果、失败、清除、竞态逐项验证。
- [ ] 语音搜索：允许、拒绝、监听、停止和系统中断逐项验证。
- [ ] 点击真实问题通知后，在首页叠加正确的未揭示卡。
- [ ] 通知卡不存在时可恢复，不出现空白遮罩。

### 15.5 证据要求

- 每个关键状态保留截图或录屏，并记录进入路径。
- 点击可用性必须通过实际点击验证，不能只看截图或读代码。
- 自动测试说明覆盖了哪条外部行为；Store Stub 成功不能替代真实上传。
- 验收报告必须单列“未验证项”，不能把历史构建或旧 Bundle 的结果沿用到新构建。

## 16. MVP 暂不包含

- 单抽与十连抽切换。
- 分类抽、关键词选池和领域筛选。
- 用户可见的文字保底机制。
- 用户纠正 AI 内容或生成答案。
- 溯源失败后手动补链接与升格。
- 主动推荐知识。
- 中途关闭按钮和半轮跨启动恢复。
- 账号体系、跨设备同步与正式生产发布。
- 具体 IP 形象与高级动画的重新设计。
- 敲击背面等系统手势快捷触发。

## 17. 请产品重点复核的边界

本文已给出可实施的默认规则，但以下体验最容易产生不同理解，请产品审阅时重点确认：

1. 空库 IP：当前定义为不抽卡且不表现成按钮；是否需要点击后用 IP 动作再次指向加号。
2. 并行上传：当前定义为处理一张截图时加号仍可用；新截图会形成独立处理项。
3. 离开半轮：当前定义为进入知识库/Profile/Settings 后结束当前半轮，返回需重新点击 IP。
4. 处理失败：当前 MVP 只提供重试或重新上传，不提供用户编辑 AI 结果或补来源链接。
5. 通知叠卡：当前定义为完成后回到通知前的首页状态，不改变底层牌组。
6. Share Extension 首次授权：当前定义为先打开 Omo 完成授权，再继续同一截图；需确认是否接受这一步额外跳转。

这些边界一经产品确认，就应转化为自动状态测试和最终 TestFlight 真机验收步骤。
