# Omo 知识库浏览与搜索 PRD

版本：MVP 0.1  
更新：2026-08-03  
状态：实施中；本地 mock 搜索不代表生产向量服务已上线

## 产品目标

当用户想使用曾经保存的知识，却只剩模糊印象时，知识库应让用户用浏览、文字描述或语音描述快速找回已有的完整知识卡片。它不是复习流程：知识库内的卡片不刮开、不提问，直接显示整理好的完整知识。

## 用户故事

- 作为已经保存过截图的用户，我进入知识库即可看到全部完整知识卡片。
- 当卡片太多时，我可以描述“我想找的知识”，获得相关卡片，而不用记住标题或准确关键词。
- 不方便打字时，我可以口述查询，并在转写后直接获得搜索结果。
- 结果放不下一页时，我可以横向翻页，并始终知道自己位于第几页。
- 我可以打开任一卡片查看完整上下文，也可以从知识库继续上传截图。

## 入口与页面结构

1. 首页收藏夹进入知识库。
2. 返回按钮回到首页。
3. 顶部搜索框包含文字输入、清除、麦克风和“帮我找”。
4. 主体展示两列错落完整卡片。
5. 底部页点显示分页位置；加号进入已有照片选择与上传流程。
6. 点击卡片进入已有“完整知识”详情。

## 文字搜索

- 空查询展示全部卡片。
- 键盘 Search 和“帮我找”执行同一提交动作。
- 输入过程不自动发请求；用户提交后才检索。
- 清空输入立即取消未完成请求、恢复全部卡片并回到第一页。
- 新请求取消旧请求；旧响应即使晚到也不得覆盖新结果。
- 结果按相关性排序，但不显示内部相似度分数。
- 未知、重复或已删除的返回 ID 会被过滤。

## 语音搜索

- 点击麦克风后按需请求语音识别和麦克风权限。
- 监听时实时更新输入框；再次点击可停止。
- 最终转写非空时自动提交一次搜索。
- 权限拒绝、识别器不可用和转写失败分别反馈；文字搜索始终可用。
- 不保存原始音频，搜索层只接收转写后的文字。
- Simulator 使用显式 Debug 转写注入验证交互；真机识别质量不属于本轮已验证能力。

## 卡片与分页

- 卡片完整显示 `coreKnowledge`，不截断。
- 合法 `hiddenSemantic` 可用字重和颜色强调，但绝不遮挡。
- 稀有度仅用于视觉装饰，不代表相关度、抽取概率或掌握程度。
- 卡片最终高度由实际 SwiftUI 排版测量决定，不按字数硬编码；首帧只用统一占位高度避免等待排版，实测值随后成为唯一分页依据。
- 每页采用两列错落布局；按结果顺序放入较短列，放不下时进入下一页。
- 查询、卡片、容器尺寸或 Dynamic Type 改变时重新分页并回到第一页。
- 横向滑动切页；页点动态反映真实页数和当前位置。

## 页面状态

| 状态 | 触发 | 页面行为 | 主要恢复动作 |
|---|---|---|---|
| 全部卡片 | 查询为空 | 展示全部完整卡片 | 搜索或打开卡片 |
| 编辑中 | 输入未提交 | 保留当前卡片 | 提交／清除 |
| 搜索中 | 提交非空查询 | 显示真实加载反馈，避免操作旧结果 | 等待或清除 |
| 有结果 | 返回至少一张卡 | 分页展示相关卡片 | 打开、改查、清除 |
| 无结果 | 成功返回空数组 | 明确“没有找到”，不伪装失败 | 查看全部／改查 |
| 搜索失败 | 超时或服务错误 | 保留查询，显示失败原因 | 重试／清除 |
| 空知识库 | 没有任何卡片 | 说明需要先上传截图 | 上传 |
| 语音监听 | 权限通过并开始采集 | 实时转写与监听态反馈 | 停止 |
| 语音受限 | 拒绝、不可用或失败 | 说明原因，保留文字输入 | 设置／重试／打字 |

## 搜索数据边界

iOS 依赖 `KnowledgeLibrarySearching`，输入是查询与当前用户已加载卡片构成的候选文档，输出是相关性有序的卡片 ID。UI 不依赖具体 embedding、向量库或模型。

本 MVP 的 Debug/test 构建使用确定性的合成 mock：它只用于页面开发、自动测试与 Simulator 状态复现，不得被称作真实向量或语义检索。Release 默认使用不可用 Adapter，直到后端真实服务实现并通过权限、索引、删除一致性、延迟与质量验证。

未来真实服务必须：

- 只检索鉴权用户自己的卡片；
- 与卡片新增、更新和删除保持索引一致；
- 返回稳定有序且属于候选集合的卡片 ID；
- 支持取消、超时和明确错误；
- 不向客户端返回 embedding 或内部相似度；
- 遵循查询与语音转写的隐私披露和保留策略。

## 可访问性与系统行为

- 所有操作目标至少 44 × 44 pt。
- 视觉旋转不改变 VoiceOver 阅读顺序；一张卡作为一个完整按钮元素。
- 页点整体读作“第 X 页，共 Y 页”。
- 搜索完成、无结果、失败与语音状态有可感知反馈。
- 支持 Dynamic Type、Reduce Motion、键盘焦点和安全区；不得横向溢出。
- 固定品牌浅色外观在系统深色模式下仍需满足文字对比度。

## MVP 非目标

- 生产 embedding、向量数据库与索引任务。
- 分类、标签、筛选、知识图谱、推荐、搜索历史和卡片编辑。
- 修改主动回忆抽卡、刮刮乐、自评或调度。
- 根据搜索内容生成新卡片或改写旧卡。

## 事件定义

本轮只冻结事件名称，不引入新的分析 SDK：

- `knowledge_library_opened`
- `knowledge_library_search_submitted`（`input_method`: `text|voice`）
- `knowledge_library_search_completed`（结果数量、页数、耗时桶；不记录原始查询）
- `knowledge_library_search_failed`（错误类别；不记录原始查询）
- `knowledge_library_card_opened`
- `knowledge_library_page_changed`
- `knowledge_library_upload_opened`

不得把原始查询、转写文本或卡片全文直接写入分析事件。

## 验收标准

- Figma node `884:324` 的橙色背景、奶油面板、返回/角色、搜索框、错落卡片、页点、收藏夹和上传结构可辨识还原。
- 全部卡片、文字搜索、语音模拟、加载、有结果、无结果、失败、空库、详情和上传均可从 Debug App 稳定复现。
- 长短卡片完整显示，分页由真实测量高度决定。
- 请求竞态、去重、失败重试、分页算法和语音衔接有自动测试。
- 常见与不同尺寸 iPhone、Dynamic Type、Reduce Motion、VoiceOver、键盘和安全区经过 Simulator/人工验收并保存截图证据。
- PR 明确列出未验证的生产向量检索和真机语音能力。
