# 主动回忆交互修正规格

- 日期：2026-07-29
- 状态：已确认方案，待书面复核
- 基线：`codex/figma-active-recall-home@c8077af`
- 目标：在团队当前简洁前后端架构上，完整恢复已经确认的主动回忆交互

## 1. 问题

当前实现把团队 Demo 的内容结构与已确认的首页视觉拼在了一起：卡片先显示 `recallCue`，再把独立的 `answer` 整块遮住。它虽然保留了刮动和自评控件的外形，但已经改变了产品的核心行为。

正确行为是：卡片直接展示一条完整、可理解的 `coreKnowledge`，只遮住其中承担核心意义的连续片段 `hiddenSemantic`。用户先根据剩余上下文主动回忆，再刮开该片段进行核对，最后报告真实记忆状态。

## 2. 已选方案

保留当前 `MemoryCard`、`OmoStore`、上传接口、存储和 assessment 调度架构，只恢复缺失的 `hiddenSemantic` 数据合同，并把旧版已确认的卡片、刮开、自评和换卡状态机移植到当前首页。

不采用以下方案：

- 不在 iOS 端从 `answer` 或 `coreKnowledge` 猜关键词。
- 不继续把独立 `answer` 整块作为刮开区域。
- 不在本次修复中回迁旧版完整 V2 来源恢复与多卡生成架构。

## 3. 卡片内容合同

`MemoryCard` 增加 `hiddenSemantic`。正式进入主动回忆牌组的卡片必须满足：

1. `coreKnowledge` 是一条完整、独立可理解的知识表达。
2. `hiddenSemantic` 非空，并且是 `coreKnowledge` 中大小写及字符完全一致的连续子串。
3. `hiddenSemantic` 是删去后能形成真实回忆缺口的承重语义，而不是随机词、标点或装饰信息。
4. `hiddenSemantic`、`coreKnowledge`、解释和来源继续受相同截图证据约束。

`answer` 暂时保留为旧客户端和已有接口的兼容字段，但不再驱动主动回忆卡片。服务端对新卡可把它镜像为 `hiddenSemantic`，不得让两个字段表达互相冲突的答案。

## 4. 后端生成与失败语义

生成提示要求模型同时返回 `coreKnowledge` 与 `hiddenSemantic`，并明确连续子串约束。服务端在持久化前验证该约束：

- 首次结果合法：正常保存。
- 首次结果不合法：使用原始截图输入和具体校验错误执行一次结构修复。
- 第二次仍不合法：本次卡片生成明确失败，不保存错误卡片，也不让客户端自行补猜。

来源恢复失败仍沿用当前 MVP 行为：只根据截图证据生成最低稀有度卡片。来源失败与 `hiddenSemantic` 合同失败是两类不同问题，前者不阻止生成，后者会阻止错误卡片进入牌组。

## 5. 旧卡兼容

已有记录可能没有 `hiddenSemantic`，或者字段不是 `coreKnowledge` 的连续子串：

- 仍在知识库中完整展示，用户数据不删除、不改写。
- 不进入主动回忆抽卡牌组。
- 首页可抽数量只统计满足新合同且当前到期的卡片。
- 本次不增加旧卡批量重生成或用户纠错入口。

这样可以避免前端猜题，同时把迁移范围保持在 MVP 必需边界内。

## 6. 主动回忆卡片

卡片正文只呈现 `coreKnowledge`，按以下三段连续排版：

```text
prefix + [被遮住的 hiddenSemantic] + suffix
```

- `prefix` 与 `suffix` 使用普通字重和正文色。
- 刮开后的 `hiddenSemantic` 使用更高字重与强调色，形成用户已要求的视觉权重差异。
- 遮罩只覆盖 `hiddenSemantic` 的实际文字区域，不覆盖整段答案或整张卡。
- 原截图不出现在复习卡片上。
- 稀有度只通过下一层卡片的微弱光效表达，是视觉装饰，不是必须点击或确认的交互步骤。
- 卡片详情入口可展开完整知识、解释和来源，但不改变当前刮开进度。

## 7. 刮刮乐状态

每张卡独立维护刮开覆盖率：

- `0%`：covered。
- `0% < coverage < 80%`：scratching；只显示用户实际刮到的对应区域。
- `coverage >= 80%`：立即归一为 `100%`，完整揭示 `hiddenSemantic`，触发一次轻震动，并显示自评滑条。

达到 80% 之前不得显示自评滑条。揭示前，`hiddenSemantic` 不得出现在可见界面、VoiceOver label/value/hint 或无障碍树中。Reduce Motion 只取消非必要位移动画，不改变刮开门槛和状态结果。

## 8. 四层滑动自评

滑条从左到右包含四层语义位置：

1. 最左端：取消区，不是 assessment。
2. 忘记了：`forgot`。
3. 没记清：`fuzzy`。
4. 记住了：`remembered`。

交互规则：

- 滑块初始位于最左端。
- 拖动跨入三个 assessment 节点时各触发一次轻震动。
- 轨道填充、描边或投影随当前节点改变，帮助用户确认选择，但不增加额外文字步骤。
- 在 assessment 节点松手即确认并提交。
- 拖回最左端松手即取消；滑块复位，当前卡不切换。
- 提交期间禁止重复提交；失败时保留已揭示卡片和原 assessment，提供原地重试。

自评只影响现有服务端 mastery 与下一次复习调度，不改变稀有度。

## 9. 一轮牌组与换卡

- 首页点击 IP 后，从当前可复习且合同合法的卡中最多取 10 张；不足 10 张则全部抽出。
- 一轮顺序在开始时冻结，中途不重新抽取。
- 自评提交成功后，当前卡从牌堆移出，下一张在首页同一位置成为顶卡。
- 卡片切换后，新卡重新从 covered 状态开始。
- 最后一张提交成功后结束本轮并回到首页的无牌组状态。
- 不增加关闭按钮，也不把做题流程导航到另一个页面。

## 10. 数据流

```text
截图上传
→ 后端生成 coreKnowledge + hiddenSemantic
→ 校验 hiddenSemantic 是连续子串
→ 保存 MemoryCard
→ iOS 只将合法且到期卡加入牌组
→ 句内刮开 hiddenSemantic
→ 80% 完整揭示
→ 滑动自评
→ POST assessment
→ 成功后原地换下一张
```

## 11. 测试与验收

后端：

- 新卡返回合法 `hiddenSemantic`。
- 非连续子串触发一次修复；二次失败不持久化。
- screenshot-only 卡仍可生成且固定为最低稀有度。
- 旧卡读取不丢失，但不会被错误改写。
- remembered / fuzzy / forgot 的现有状态机保持通过。

iOS：

- `MemoryCard` 正确解码新字段，并识别是否可进入主动回忆。
- 句首、句中、句尾和重复出现的 `hiddenSemantic` 都有确定分段行为；默认遮住第一次匹配。
- 79% 不显示自评，80% 立即完整揭示并显示自评。
- 最左端松手取消，三个节点松手分别提交正确值。
- 提交失败不换卡，重试成功只换一次。
- 牌组最多 10 张，旧卡或非法卡不进入牌组，知识库仍显示完整内容。

模拟器人工检查：

- 常见 iPhone 尺寸与一个小尺寸设备。
- covered、partial scratch、revealed、三个自评节点、取消、提交失败与下一张状态。
- 触控区域、安全区、Dynamic Type、Reduce Motion 和 VoiceOver 不泄露答案。

## 12. 非目标

- 不调整 IP 形象和动画创意。
- 不重做知识库次级页面。
- 不新增旧卡批量修复、用户纠错、单抽/十连抽切换或通知卡。
- 不改变稀有度定义、概率或调度算法。
- 不证明真实 Qwen、TickHub、APNs 或生产部署已通过；没有真实凭据时只报告本地合同与 Fixture 验证。

## 13. 自检结果

- 无 TBD、TODO 或未决占位。
- 交互、数据合同和失败语义一致。
- 范围聚焦于主动回忆主线，可作为一个跨 iOS、后端和稳定文档的实施计划。
- `answer` 的兼容角色、旧卡行为、80% 门槛和取消语义均已明确。
